# Project

## Purpose

This section defines the project's foundational context.

It explains why the project exists, what it aims to achieve, its intended scope, and the shared terminology used throughout the Engineering Handbook.

The documents in this section provide the context required to understand every other part of the system.

---

# Contents

| Document | Purpose |
|----------|---------|
| **01-Vision.md** | Defines the long-term vision and strategic direction of the project. |
| **02-Scope.md** | Defines the project's boundaries, objectives, and non-goals. |
| **03-ProjectContext.md** | Describes the project's background, current context, and overall objectives. |
| **04-Glossary.md** | Defines the shared business and technical terminology used throughout the handbook. |

---

# Reading Order

New contributors are encouraged to read the documents in the following order:

1. Vision
2. Scope
3. Project Context
4. Glossary

This sequence provides the necessary context before exploring the product, architecture, or implementation details.

---

# Responsibilities

This section is responsible for documenting:

- Project vision.
- Project scope.
- Project context.
- Shared terminology.

This section should not document:

- Product functionality.
- Business modules.
- Software architecture.
- Technical implementation.
- Development practices.

Those topics belong to their respective sections of the Engineering Handbook.

---

# Relationship with Other Sections

The Project section serves as the foundation of the Engineering Handbook.

The information documented here provides context for every other knowledge domain, including:

- Product
- Architecture
- Modules
- Backend
- Frontend
- API
- Data
- Development
- Quality
- DevOps

Every contributor is expected to understand the project context before making architectural or implementation decisions.
